Privacy-preserving machine learning

Classify a digit the server never sees

The client encrypts every 3×3 patch of the image with inner-product functional encryption. The server holds one functional key per convolution kernel, so it learns the first-layer outputs ⟨patch, kernel⟩ and nothing else about the pixels. Everything below runs locally in your browser.

2

Generate keys

client

The client picks a prime p, a generator g of ℤp* and a secret vector s (the master key). It publishes hi = gsi and derives one functional key sky = ⟨s, y⟩ per kernel y. Only these keys are sent to the server.

3

Encrypt the patches

client

The image is cut into 10×10 = 100 patches of 3×3 pixels (stride 3, zero padding). Each patch x is encrypted as ct0 = gr, cti = hir · gxi with fresh randomness r. Hover over a patch to inspect it.

4

Decrypt only the inner products

server

For each kernel y the server computes ∏ ctiyi / ct0sky = g⟨x,y⟩ and recovers ⟨x,y⟩ with a baby-step giant-step discrete log. Adding the bias gives exactly one value of the first convolution. Top row: decrypted feature maps. Bottom row: the same convolution computed in plaintext, for comparison.

5

Finish the network and predict

server

The remaining layers run in plaintext on the decrypted feature maps.

What this demo does not claim

  • Toy parameters. p ≈ 8 × 106 keeps the discrete log fast. Real DDH security needs 2048-bit groups or elliptic curves.
  • Only the first layer is encrypted. The server learns the first-layer feature maps, which leak partial information about the input.
  • The client sees the first-layer kernels. It acts as key authority, so it needs y to derive sky.
